# Package A — implementation plan

Date: 2026-11-02 · Spec: `docs/superpowers/specs/2026-11-02-isar-flow-packages-design.md` (Package A, sections A1–A5).
Exclusion confirmed by the owner: **no MCP server** for Claude Code or other external agents — no module builds one.

Package A makes runs trustworthy: a safety net for file changes (A1), agents that work with local models (A2),
time and tokens per block (A3), clear capabilities (A4) and a setup check (A5). Six modules build it in parallel
against frozen contracts; an integration step wires the last pieces, runs the slow test levels once and writes
the docs.

## 2. Rules for every module

- Read the spec (Package A), this plan and, for UI work, `docs/ui-design.md`.
- Edit only the paths your module owns. Other modules work at the same time: ignore their in-progress files and
  type errors outside your paths. Never edit the frozen contract files (section 1).
- No git state changes in the repository (no commit, stash, checkout, reset, add). Snapshot tests create
  temporary repositories under `os.tmpdir()` and may create refs only there. No `npm install`.
- TDD: failing test first, then the implementation. Style: 2 spaces, single quotes, printWidth 110, prettier,
  no `any`, small focused files, comments only when non-obvious. User-facing copy: sentence case, plain verbs,
  actionable errors. Never lose user data.
- Machine limits (Windows 11, 6 GB RAM, a GPU driver that can freeze the machine):
  - Vitest: run your project and paths only (`npx vitest run --project core packages/core/test/agent`); add
    `--maxWorkers=2` for whole-project runs.
  - Integration tests (`npm run test:integration -w isar-flow`): only after
    `packages/extension/test/integration/runTests.mjs` passes `--disable-gpu` (ext-safety adds it first — check
    with grep; if it is missing, do not run them). Only one VS Code test instance at a time: take the lock by
    creating the directory `%TEMP%\isarflow-vscode-test.lock` with `mkdir` (atomic); if it exists, wait
    (PowerShell `Start-Sleep 30`) and retry; always remove it afterwards, also on failure. Use `ISAR_TEST_GREP` to
    run only your tests.
  - Playwright (`scripts/visual.mjs`, `scripts/interactions.mjs`): one browser at a time with the same protocol
    and the lock directory `%TEMP%\isarflow-playwright.lock`; always pass `--only=…` (and for visual runs
    `--themes=dark,light,hc` only when needed). Read the PNGs in `packages/webview-ui/visual-output/`; zero page
    errors required.
- Commands: `npx vitest run --project <core|extension|webview-ui> [paths]`,
  `npx tsc --noEmit -p packages/<pkg>/tsconfig.json`, `npx eslint <paths>`, `npx prettier --check <paths>`.
- Done means: your tests pass; `tsc` passes for every package you touched (errors that are only in other modules'
  in-progress files are acceptable — name them); eslint and prettier are clean on your files. The final report
  lists the changed files, contract change requests, things the integrator must wire, and short user-guide
  snippets for your features (docs are written in the integration step; do not edit `docs/`, `README.md`,
  `CHANGELOG.md` or `examples/`).

### 3.1 agent-loop — compaction, tool-call repair, toolMode, tool calls count (A2, core)

**Owns:** `packages/core/src/agent/**` except `types.ts`; `packages/core/src/yaml/templates.ts`;
`packages/core/test/agent/**`; `packages/core/test/yaml/templates.test.ts`;
`packages/core/test/fakes/fakeModel.ts`; `packages/core/test/fakes/mockOpenAIServer.ts`.

**Consumes:** `ToolMode`, `ToolName` incl. `applyPatch`; `AgentLoopOptions.toolMode / contextTokens`,
`AgentLoopResult.toolCalls`, `AgentRequestDeps.contextTokens`, `AgentResult.toolCalls`,
`ResolvedAgent.toolMode` (via `AgentSettings`), `ChatModelInfo.maxInputTokens`, `capabilities.tools`.

**Produces:**

- `executeAgentRequest` passes `request.agent.toolMode` and `deps.contextTokens` to the loop and returns
  `AgentResult.toolCalls` summed over all models of the block (fallbacks included).
- `runAgentLoop` / `continueConversation` return `toolCalls`; the counter lives in `Conversation` so a fallback
  model continues it. Every executed call counts (native, repaired, text mode; refused and failed ones too).
- Tool specs: `editFile` description for tolerant matching ("…matched exactly; if not found, line endings and
  then whitespace per line are ignored; indentation comes from the file; the match must be unique…");
  `applyPatch` spec may be refined (keep the parameter `patch: string`, required); `describeToolCall('applyPatch')`
  lists the files of the patch headers (`applyPatch src/a.ts, src/b.ts` or `applyPatch 4 files`).
- Templates: Coder starter gets `applyPatch` after `editFile` and a system-prompt line ("use applyPatch for changes
  in several places or files"); the Blank starter (`newAgentText`) comment reads: `# Read-only: it can look at
files but not change them. Add editFile, applyPatch or writeFile to let it change code.` (keep the YAML valid
  and the tool list read-only).

**Behavior:**

1. _toolMode._ Effective mode: `native` → native tool specs, no repair; `text` → text mode; `auto` → native plus
   repair when `model.capabilities.tools`, else text mode, logged once per block: `<model> has no native tool
calling, so the tools are described in the prompt (text tool mode).`
2. _Text mode._ No `tools` in ChatOptions. The system prompt gets a section that lists every enabled tool (name,
   description, compact JSON schema of the parameters) and the call format
   `<tool_call>{"name": "readFile", "arguments": {"path": "src/app.ts"}}</tool_call>` (several calls per reply
   allowed; answer without a call when done). The conversation stays canonical (assistant `toolCalls` + `tool`
   messages); only the copy sent to the model is converted: assistant calls → text with `<tool_call>` blocks,
   tool results → user messages `Result of readFile (call_3):\n…` (`Error from …` for errors). Fallback models
   therefore continue across modes, and `session: continue` stores the canonical form.
3. _Tool-call repair_ (auto and text): `parseTextToolCalls(text, enabledTools)` finds `<tool_call>…</tool_call>`
   (one or more), fenced ` ```json ` / ` ```tool_call ` blocks and bare JSON objects or arrays with
   `{name, arguments}` (object or JSON string), `{tool, args}`, `{function: {name, arguments}}`,
   `{name, parameters}`. Only enabled tool names count; anything else stays text. A found call is executed like a
   native call (ids `call_<n>`, the assistant text keeps the prose without the call markup); log once per block
   `The model wrote a tool call as text; running it.` For JSON-answer blocks a final answer counts as a call only
   when it is exactly a call shape with an enabled tool name.
4. _Malformed calls_ (an enabled tool name but arguments that are not a JSON object): one corrective user message
   `Your tool call could not be read: <problem>. Reply with only the tool call, as <tool_call>{"name": "<tool>",
"arguments": {…}}</tool_call>.` A second malformed reply in a row fails the block: `The model wrote tool calls
that could not be read twice. Set Tool calls to Text in the agent, or use a model with native tool calling.`
   Corrective rounds do not count against maxTurns (like the JSON repair round).
5. _Compaction_ (`compaction.ts`): before each model turn estimate tokens = ceil(chars / 4) over the system
   prompt, messages (content and tool-call arguments) and the tool specs (JSON) or the text-mode tool section.
   Limit = `model.maxInputTokens ?? options.contextTokens ?? 24000`; compact above 70 %. Keep verbatim: system
   prompt, the first user message (task with context files and JSON instructions) and the latest tool exchange
   (last assistant message with calls plus all its results). Replace everything between with one user message
   `Summary of the earlier work (older messages were removed to save context):\n<summary>`. The summary comes from
   the same model without tools (temperature 0, maxTokens 1024) with the instruction to keep file paths,
   decisions, findings, errors and open work in at most 300 words; the middle is rendered as plain text with each
   tool result clipped to 2,000 characters. Never separate an assistant call from its tool results. Its usage
   counts toward the block; it is not a turn. Log `Compacted the conversation: 24 older messages (about 19,800
tokens) replaced by a summary (about 450 tokens).` On abort rethrow; on other errors log `Could not compact the
conversation: <message>. Continuing with the full conversation.` and go on. At most one compaction per turn;
   if still over the limit, warn once. Fewer than two middle messages → no compaction.

**Edge cases:** models that send both text and native calls (native wins, text kept); calls without ids; unknown
tool names in text; nested JSON in arguments; `<tool_call>` with trailing commas or single quotes (try a lenient
JSON parse, then treat as malformed); aborts during the summary request; a fallback model in a different mode;
`maxInputTokens` smaller than the system prompt; empty middle.

**Tests (core unit, FakeModel):** every repair format; unknown tool ignored; malformed → corrective → success;
malformed twice → failure text; native mode ignores text calls; JSON-answer blocks not misread; text mode sends no
tools, describes them in the system prompt, sends results as user messages; fallback from a text-mode model to a
native model continues the conversation; compaction thresholds (maxInputTokens vs contextTokens vs default),
verbatim parts, intact call/result pairs, usage includes the summary, failure continues, abort rethrows, log
line; `toolCalls` counts in the loop and across fallbacks in `executeAgentRequest`; `describeToolCall` for
applyPatch; templates (Coder has applyPatch; Blank comment). Extend `test/fakes/fakeModel.ts` as needed
(`maxInputTokens`, `capabilities.tools: false`, scripted text calls).

### 3.2 edit-tools-metrics — applyPatch, tolerant editFile, journal hook (A2/A1, extension) and run metrics (A3, core)

**Owns:** `packages/extension/src/tools/**`; `packages/extension/test/unit/tools/**`;
`packages/extension/test/integration/suite/7-agent-tools.test.ts` (new);
`packages/core/src/engine/**` except `types.ts`; `packages/core/src/run/**` except `types.ts`;
`packages/core/src/variables.ts`; `packages/core/src/validate.ts`; `packages/core/test/engine/**`;
`packages/core/test/run/**`; `packages/core/test/variables.test.ts`; `packages/core/test/validate.test.ts`;
`packages/core/test/fakes/fakeHost.ts`; new `packages/core/test/metrics/**`.

**Consumes:** `BUILTIN_TOOLS.applyPatch` (parameter `patch`), `TOOL_INFO`, `WorkspaceAdapter.deleteFile?`,
`EditJournalWriter`, `ToolHostOptions.journal`, `ToolHostRunOptions`, `ToolHostFactory` third parameter,
`AgentResult.toolCalls`, `StepMetrics`, `BlockRunMetrics`, `RunRecordSummary.blocks`, `Workflow.isolation/setup`,
`ToolMode`.

**Part A — tools (extension):**

1. _Tolerant editFile_ (pure matcher in `tools/tolerantMatch.ts`): modes in order — exact (today's CRLF handling
   counts as exact) → line-ending-normalized → whitespace-insensitive per line (each line compared trimmed with
   inner whitespace runs collapsed; leading and trailing blank lines of oldText ignored). Each mode needs exactly
   one match; more than one stops with `oldText matches 3 places in <path> (ignoring whitespace). Include more
surrounding lines so it matches exactly once.`; zero falls through. In whitespace mode newText is re-indented:
   the indentation of oldText's first non-blank line is replaced by the file's matched indentation on every line
   that starts with it (relative indentation kept; tabs/spaces from the file); line endings follow the file. The
   result says the mode: `… (matched after normalizing line endings)` / `… (matched ignoring whitespace;
indentation taken from the file)`. Planning again after `authorize` stays.
2. _applyPatch_ (`tools/unifiedDiff.ts` parser, `tools/patchApply.ts` matcher, `tools/patchTool.ts` tool;
   replace the placeholder in `toolHost.ts`). Parser accepts prose and code fences around the diff,
   `diff --git` / `index` lines, `a/` `b/` prefixes, tab-separated timestamps, quoted paths, `--- /dev/null`
   (create), `+++ /dev/null` (delete), `\ No newline at end of file`, hunks without counts (`@@ -12 +12 @@`) and
   without numbers (`@@ @@`: search the whole file), CRLF patch text. Renames, copies and binary patches are
   refused with a clear message; the same file twice in one patch is an error. Matching per hunk: expected lines =
   context + removed lines; try the stated line (shifted by earlier hunks' offsets), then outward up to ±200 lines
   nearest first, then the whole file if unique; compare lines with trailing whitespace and `\r` ignored, then
   whitespace-collapsed (re-indent added lines like editFile). Hunks of a file apply in order and must not
   overlap; the file keeps its line endings and its final-newline state. **All or nothing:** every file's new
   content is planned first; any failure changes nothing and the result lists each failing hunk, e.g. `src/app.ts
hunk 2 (@@ -40,7 +40,8 @@): the context was not found near line 40; first differing line: "return total;".
Read the file again and make a new patch.` Create: the file must not exist; delete: it must exist and match the
   removed lines. One `authorize('applyPatch', summary, detail)` per call: `Patch src/app.ts` / `Patch 3 files`,
   plus `(creates 1, deletes 1)` when it applies; detail = the patch clipped to 800 characters. After authorize:
   recheck paths, plan again on fresh text, then write files in path order (deletes via
   `workspace.deleteFile`; error before any write when the adapter has none). Success text: `Patched 3 files:
src/a.ts (+4 −1), src/b.ts (+2 −2), src/c.ts (new, +10).` with notes for hunks applied with an offset or
   ignoring whitespace. A write failure part-way restores the files already written from the originals read
   before and reports what happened. Same path rules as editFile (workspace only, no `.git`, not the folder).
3. _Journal hook:_ when `options.journal` is set, the per-call workspace given to tools calls
   `await journal.beforeWrite(absPath, io.stepId)` before every `writeFile` and `deleteFile` (not for reads).
   `createToolHostFactory` passes the third parameter through; Try it (no options) is unchanged.
4. _VS Code adapter:_ `deleteFile` via `WorkspaceEdit.deleteFile` + `applyEdit` (undoable). Roots outside the
   workspace folders (git worktrees in extension storage) must work: when `root` is not inside a workspace folder
   (or `findFiles` throws) walk the folder with node `fs` (skip `node_modules`, `.git` and symlinked folders,
   stop at `max`) and match with a small glob matcher (`tools/glob.ts`: `**`, `*`, `?`, `{a,b}`, `[abc]`).

**Part B — metrics (core):**

1. Agent block output adds `toolCalls` (`result.toolCalls ?? 0`); keep `text, json, model, usage, turns`.
2. `engine/agents.ts` `resolveAgent` copies `toolMode` (add to `SETTING_KEYS`).
3. `reduceRunEvent`: on every `step-end` that is not `skipped`, update `StepRunView.metrics`: `durationMs +=`,
   `executions += 1`; outputs with numeric `usage` add tokens; `model` = latest string model; `turns` and
   `toolCalls` summed; loop outputs with numeric `iterations` set `iterations`. Pure; old views without metrics
   still reduce; malformed outputs are ignored.
4. `runRecordSummary` adds `blocks` for every step with metrics: `{ status, durationMs, inputTokens?,
outputTokens?, iterations? (loops: iterations; others: executions when > 1), model? }`; omit `blocks` when
   empty; never copy text or logs.
5. `variables.ts`: agent outputs list `toolCalls` ("Tool calls the agent made") so the variable picker shows it.
6. `validate.ts` warnings (with ranges like the existing ones): `setup` without `isolation: worktree` → `Setup
commands only run with isolation: worktree. Set isolation to worktree or remove setup.`; a setup command that
   contains `${{` → `Setup commands run as written; ${{ }} templates are not filled in.`

**Edge cases:** CRLF files with LF patches; tabs vs spaces; files without final newline; empty files; a hunk at
the start or end of a file; duplicate context in a file (ambiguous); large files (respect the existing size caps
of `readWorkspaceText`); a patch that deletes and creates the same path (error); permission `none`/`ask`/`auto`
and "allow for this run"; aborted runs while asking; paths through links and junctions (existing guards); loops
re-running blocks; retries inside one execution; cancelled runs (no step-end, no metrics); failed agent blocks
that used tokens.

**Tests:** tolerant matcher tables; parser fixtures (git diff, multi-file, create/delete, no-newline marker, CRLF,
fenced, missing counts, garbage → message); apply (offset drift, whitespace drift, overlap, all-or-nothing, line
endings, final newline, delete mismatch); tool host through `test/unit/tools/harness.ts` (prompt summary and
detail, `.git` and traversal refusal, recheck after authorize, journal called once per write with the step id
and before the write, missing `deleteFile`); glob matcher and the fs fallback of the adapter; core: engine agent
output `toolCalls`, `reduceRunEvent` metrics (loop executions, skipped, cancelled, failed with usage, latest
model, loop iterations), `runRecordSummary` blocks, variables, validate warnings, `resolveAgent` toolMode.
Integration (`7-agent-tools.test.ts`, lock + `--disable-gpu` only): applyPatch on an open document saves it;
`deleteFile` works and is undoable; `findFiles` under a temp folder outside the workspace.

to `executeAgentRequest`. `createRunManager` creates the safety services by default (like history and
approvals; `options.safety` for tests), so `extension.ts` does not change.

**Snapshots (`safety/gitSnapshots.ts`)** with `child_process.execFile('git', …)` (no shell), `-z` output,
`-c core.quotepath=false`, timeouts, and on Windows `-c core.longpaths=true`:

1. `rev-parse --show-toplevel` and `--show-prefix` in the folder; failure (no git, not a repository) → journal
   coverage, logged once.
2. Temporary index in extension storage: copy the user's index file (`rev-parse --git-path index`) when it
   exists (only changed files get hashed again), then with `GIT_INDEX_FILE=<tmp>`: `add -A -- .` (cwd = the
   folder), `write-tree`, `commit-tree <tree> -m "Isar Flow run <runId> (before)"` with
   `GIT_AUTHOR_NAME/EMAIL` and `GIT_COMMITTER_NAME/EMAIL` = `Isar Flow` / `isarflow@localhost`, then
   `update-ref refs/isarflow/runs/<runId>/before <commit>`; delete the temporary index. The user's index, branch,
   stash and working tree are never touched. 60 s timeout → journal coverage with a log line.
3. At run end (success, failure and cancelled) the same gives `…/after`; changes =
   `diff-tree -r -z --no-renames --name-status` and `--numstat` between the commits, limited to the folder
   (binary: numstat `-`). Paths are reported relative to the folder.
4. `read`: `cat-file --filters <commit>:<repo path>` (working-tree bytes, line endings and filters applied;
   fallback `cat-file blob`); undefined when the file is not in the tree.

**Edit journal (`safety/editJournal.ts`):** `beforeWrite` reads the file from disk once per path and run,
records the step id (more step ids appended on later writes), stores originals up to 2 MB per file and 50 MB per
run under `<storage>/reviews/<runId>/`, larger ones with `git hash-object -w` when a repository exists, otherwise
not stored (`revertible: false`). Never rejects. At run end the journal also records a hash of each journaled
file, so "changed after the run" can be detected without git.

**Review (`safety/reviewService.ts`):** files = git changes ∪ journal paths (journal coverage: journal paths with
content that differs from the original), sorted by path, capped at 500 (`omitted`); `stepIds` from the journal
(empty = a command); state in `<storage>/reviews/<runId>/review.json` (root, repo top, prefix, coverage,
isolation, worktree path, snapshot commits, decisions, errors). After every change: `history.setReview(runId,
counts)` and `onDidChange`.

- _Workspace runs:_ Keep only marks the file. Revert restores the before state (added → delete, modified → write,
  deleted → recreate with parent folders) via `WorkspaceEdit` for text (open editors update, undoable) and
  `workspace.fs.writeFile` for binary files. Before writing, compare the current file (an open dirty document
  counts) with the state right after the run; if it differs, ask in a modal: `src/app.ts changed after the run.
Revert it anyway? Your newer changes to it are lost.` (`Revert anyway` / Cancel → stays pending).
- _Worktree runs:_ Keep applies the worktree's version to the workspace (same operations); if the workspace file
  differs from the before state, ask `src/app.ts changed in your workspace during the run. Replace it with the
run's version?`. Revert only marks (the change is dropped). When no file is pending, remove the worktree
  (`worktreeAvailable: false`).
- Batch (`paths` omitted): one modal for all files that changed after the run (`3 files changed after the run:
a, b, c.` with `Revert all anyway` / `Skip changed files` / Cancel). `busy` while applying; a failure sets the
  file's `error` and leaves it pending.
- `openDiff`: `vscode.diff(left, right, title)` with left = `isarflow-snapshot:/<runId>/before/<path>`
  (empty side for added files) and right = the workspace file (workspace runs; snapshot `after` when it was
  deleted) or the worktree file; title `<file name>: before the run and now`. Binary files: message `Binary files
can't be compared.` with `Open file`.
- `overlapping`: another run was active in the same folder during this run.

**Run manager (`run/runManager.ts`):**

- At launch: `snapshots.begin(runId, folder)` and a journal; tool host via `deps.tools(runId, root, { journal })`.
- `isolation: worktree`: refuse to start without git (`Isolation "worktree" needs a git repository. Run git init
in <folder>, or set isolation to workspace.`); create `<storage>/worktrees/<runId>` at the before commit; the
  run's root = the matching subfolder of the worktree for a folder inside a larger repository; run `setup`
  commands one after the other with the console runner in that root, mirrored to the run terminal (`▶ setup: npm
ci`); a failing or cancelled setup ends the run (synthesized `run-start`/`run-end` like today's unexpected-stop
  path, error `Setup command "npm ci" failed with exit code 1. See the terminal for its output.`) and removes the
  worktree. Engine `workspaceRoot`, console cwd, agent tools and context files (`readContextFilesIn(root)`) all use
  the worktree root.
- At the end: `finish`, build the review, save it, and when files changed show `<workflow name> changed 3
files.` with `Review changes` (opens the canvas on that run via `isarFlow.internal.showRun`).
- On shutdown the after snapshot is skipped; a review without `after` takes it lazily on the first `get`.
- On creation: remove worktrees whose run has no history record or no pending file, then `git worktree prune`.
- `commandApproval.ts`: setup commands are listed (`Setup: npm ci`) and part of the approval hash.

**History (`run/history.ts`):** keep `metrics` in `skeleton()`; `setReview(runId, counts)` updates the summary in
the index and fires `onDidChange`; `onDidRemove` fires with the run ids removed by `historyLimit`; the review
service prunes refs (`update-ref -d`), journal folders, review files and worktrees of those runs.

**Workflow panel / editor:** track the run shown on the canvas (live run id from `run-start`, or the selected past
run); after every `run` message and on `reviews.onDidChange` for that run post `{ type: 'review', review }`
(null when none); handle `reviewFiles` (validate `runId`, `decision`, `paths` array of strings) and
`openReviewDiff` for runs of this workflow only. `registerWorkflowEditor` registers the `isarflow-snapshot`
content provider from `services.runs.reviews`.

**Edge cases:** non-git folders; folders inside a larger repository; git missing; empty repository without
commits; files changed after the run; binary and very large files; CRLF and autocrlf; added, deleted and
re-created files; ignored files (not in git snapshots, still in the journal); symbolic links (`revertible:
false`); submodules (pointer changes only); open dirty editors; cancelled and failed runs; VS Code closed during a
run; two runs in the same folder; worktree without git; setup failure and cancel; long Windows paths; pruning
while a review is open.

**Tests:** unit with temporary git repositories under `os.tmpdir()` (skip with a clear message when git is
missing): before/after commits leave the user's index, HEAD, stash and working tree unchanged (compare `git
status --porcelain`, the index file bytes and `rev-parse HEAD`); changes list with numstat and binary; read with
CRLF; journal-only folder; journal size caps; review decisions for every status in both isolations including the
changed-after-run prompts and batch prompts; worktree create/apply/remove; setup failure; pruning; history
`setReview`/`onDidRemove`/skeleton metrics; run manager wiring with fakes; workflow panel review messages and
validation. Integration `8-safety.test.ts`: `git init` the temp fixture workspace, run a console workflow that
changes a file, check the review, revert, and check the file.
