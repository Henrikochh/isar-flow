# Package C — implementation plan

Date: 2026-11-03 · Spec: `docs/superpowers/specs/2026-11-02-isar-flow-packages-design.md` (Package C, sections C1–C8).
Builds on Package A (`2026-11-02-package-a.md`) and Package B (`2026-11-02-package-b.md`), which are finished and
must not regress. Exclusion confirmed by the owner: **no MCP server and no MCP mode or transport** — not in the
extension, not in the command line runner. Copilot is integrated only through VS Code language model tools and a
chat participant.

Package C makes workflows part of everyday work: they read the code you are looking at (C1), start by themselves
(C2), can be run from Copilot (C3), reach you while the canvas is hidden (C4), ask questions (C5), keep project
memory (C6), export a run report (C7) and run from a terminal (C8). Seven modules build it against frozen contracts
in two waves; an integration step wires the rest, runs the slow test levels once and writes the docs.

### 1.5 Sharing Node code with the command line (decision)

- **`@isar-flow/core/node`** is a second, Node-only entry of the core package (`"exports": { ".": …, "./node":
"./src/node/index.ts" }`). The main entry stays isomorphic because the webviews import it.
  `packages/core/test/node-boundary.test.ts` enforces: nothing outside `core/src/node/` uses `node:` imports,
  `require(`, `process.env|cwd|platform|argv` or imports `src/node`; the webviews never import `@isar-flow/core/node`.
- **Console runner and agent tool host** move from `packages/extension/src/runner/**` and `src/tools/**` (the
  vscode-free files) into `core/src/node/runner/**` and `core/src/node/tools/**` (module cli, Part A). Every moved file
  that remaining extension code imports stays as a one-line re-export shim, so no other module's imports change.
- **OpenAI-compatible model access** is already isomorphic (`OpenAICompatClient` in the core main entry, `fetch`
  only). The command line builds its own small resolver from `.isarflow/config.yaml` / environment variables; VS Code
  keeps its registry.
- **Git capture** (`captureGitContext`) lives in `core/src/node/git/**` and is used by the extension (C1) and the
  command line.
- `packages/cli` resolves `@isar-flow/core` through the existing root `node_modules` symlink (no npm install). esbuild
  bundles core, `yaml` and `zod` into `dist/cli.js` (ESM, Node 20, shebang, `createRequire` banner);
  `node packages/cli/dist/cli.js` runs it. Root `package.json` lists the workspace and `build:cli`; `vitest.config.ts`
  has the `packages/cli` project (coverage excludes only `packages/cli/src/index.ts`).

## 2. Rules for every module

- Read the spec (Package C), this plan, the v1 spec §11 (test concept) and, for UI work, `docs/ui-design.md`.
- Edit only the paths your module owns. Other modules work at the same time: ignore their in-progress files and type
  errors outside your paths. Never edit the frozen contract files (section 1). Do not regress Packages A and B. You
  may import existing exports of other modules' files (read-only).
- **No MCP**: no MCP server, MCP client, MCP transport, `mcp` subcommand, `--stdio` / `serve` mode or MCP dependency
  anywhere.
- No git state changes in the repository (no commit, stash, checkout, reset, add). No `npm install`, no new external
  dependencies (Node built-ins such as `node:util` `parseArgs`, `node:readline`, `node:child_process` `execFile` /
  `spawn` are fine; esbuild, vitest and typescript are installed at the root).
- TDD: failing test first, then the implementation. Style: 2 spaces, single quotes, printWidth 110, prettier, no
  `any`, small focused files, comments only when non-obvious. User-facing copy: sentence case, plain verbs,
  actionable errors; no "A · B" meta strings (separate chips or spans), no "→" in buttons. Never lose user data.
- Machine limits (Windows 11, 6 GB RAM, a GPU driver that can freeze the machine):
  - Vitest: run your project and paths only (`npx vitest run --project core packages/core/test/ask`); add
    `--maxWorkers=2` for whole-project runs.
  - Integration tests (`npm run test:integration -w isar-flow`): only one VS Code test instance at a time, always
    with `--disable-gpu` (already in `packages/extension/test/integration/runTests.mjs` — check with grep; if it is
    missing, do not run them). Take the lock by creating the directory `%TEMP%\isarflow-vscode-test.lock` with `mkdir`
    (atomic); if it exists, wait (PowerShell `Start-Sleep 30`) and retry; always remove it afterwards, also on
    failure. Use `ISAR_TEST_GREP` to run only your tests. `test/integration/helpers.ts` belongs to ext-host; other
    modules import its existing helpers or keep local helpers in their own suite file. Files a suite needs are
    created at test time in the temporary workspace copy and deleted afterwards (other suites count the fixtures).
  - Playwright (`scripts/visual.mjs`, `scripts/interactions.mjs`): one browser at a time with the lock directory
    `%TEMP%\isarflow-playwright.lock` (same protocol); always pass `--only=…` (and `--themes=dark,light,hc` only when
    needed). Read the PNGs in `packages/webview-ui/visual-output/`; zero page errors required.
- Commands: `npx vitest run --project <core|extension|webview-ui|cli> [paths]`,
  `npx tsc --noEmit -p packages/<pkg>/tsconfig.json`, `npx eslint <paths>`, `npx prettier --check <paths>`.
- Done means: your tests pass; `tsc` passes for every package you touched (errors only in other modules' in-progress
  files are acceptable — name them); eslint and prettier are clean on your files; coverage gates hold (core ≥ 90 %,
  extension ≥ 70 %). The final report lists changed files, contract change requests, things the integrator must
  wire, and short user-guide snippets for your features (docs are written in the integration step; do not edit
  `docs/`, `README.md`, `CHANGELOG.md` or `examples/`).

### 3.1 core-blocks — ask block, editor and git roots, origin, triggers helpers (C1, C2, C5 core)

**Owns:** `packages/core/src/engine/**` except `types.ts`; `packages/core/src/run/**` except `types.ts`;
`packages/core/src/live/**`; `packages/core/src/simulation/**`; `packages/core/src/triggers/**` except `types.ts`;
`packages/core/src/yaml/**` except `types.ts`; `packages/core/src/expr/**`; `packages/core/src/validate.ts`;
`packages/core/src/variables.ts`; tests `packages/core/test/{engine,run,live,simulation,resume,yaml,expr,metrics}/**`,
`packages/core/test/validate*.test.ts`, `packages/core/test/variables.test.ts`, `packages/core/test/fakes/fakeHost.ts`,
new `packages/core/test/ask/**`, `packages/core/test/triggers/**`, `packages/core/test/roots/**`.

**Produces** (exported from `@isar-flow/core` through the existing sub-barrels; `triggers/index.ts` exports the new
trigger files next to `types`):

- `parseDuration(text: string): number | undefined` — sum of `<int><s|m|h|d>` parts in ms; undefined for anything
  that does not match `DURATION_PATTERN` or is 0. `MIN_SCHEDULE_MS = 60_000`.
- `formatEvery(ms: number): string` — "Every 15 min", "Every hour", "Every 2 hours", "Every 1 h 30 min",
  "Every day", "Every 3 days", "Every 1 min 30 s" (one unit of 1 → the word; one unit > 1 → number + unit; several
  units → abbreviations d / h / min / s).
- `triggerSummaries(on: unknown): TriggerSummary[]` — defensive (lenient models); order save, change, schedule;
  `files` always a list (string → [string]; non-strings and empty strings dropped; a trigger without usable patterns
  is left out); labels "On save: src/*.ts", "On change: docs/**, !docs/gen/**" (at most 3 patterns, then
  " and 2 more"), schedule label `formatEvery(everyMs)` or "Every <as written>" when unparsable (`everyMs`
  undefined).
- `workflowUsesRoot(workflow: Workflow | null | undefined, root: 'editor' | 'git'): boolean` — any `${{ }}` template or
  condition in blocks (all fields that are rendered), workflow `env`, or input defaults references the root
  (`analyzeExpression` references; unparsable expressions ignored).
- `EDITOR_FIELDS = ['selection', 'file', 'language', 'line'] as const`, `GIT_FIELDS = ['branch', 'changedFiles',
'diff'] as const`; `emptyEditorContext(): EditorContext` (`''`, `''`, `''`, 0); `emptyGitContext(): GitContext`
  (`''`, `[]`, `''`).
- `runOriginText(origin: RunOrigin | undefined): { chip: string; sentence: string; icon: string } | undefined` —
  undefined for manual/missing. trigger save: "On save" / "Started on save of src/app.ts" (without file: "Started on
  save") / `save`; change: "On change" / "Started by a change to docs/a.md" / `file`; schedule: "Scheduled" /
  "Started by its schedule" / `watch`; copilot: "Copilot" / "Started by Copilot" / `copilot`; selection: "Selection" /
  "Started on a selection" / `selection`; cli: "Command line" / "Started from the command line" / `terminal`.
- `parseProjectConfigText(text: string): ProjectConfigParseResult` (new file in `yaml/`, exported from
  `yaml/index.ts`): YAML + `ProjectConfigSchema` diagnostics with ranges like the other parsers; empty text → valid,
  `{}`.
- Engine, view, live, simulation, validation and variables changes below.

**Behavior:**

1. _Ask leaf_ (`engine/leaves.ts` + dispatch in `engine.ts`): prepare renders `question` (field `question`), each
   choice (`choices[i]`) and `default`; detail = question. A choice that renders empty → setup error "Choice 2 of
   'pick' is empty after its template was filled in."; duplicates after rendering are dropped (first kept). Rendered
   choices + default not among them → setup error "The default 'x' of 'pick' isn't one of its choices: a, b."
   Invoke: `host.askUser` missing → answer = default ?? first choice; neither → failure "Nobody can answer 'pick'
   here. Give it a default." Otherwise call `askUser({ stepId, question, choices?, default?, timeoutMs? }, io)`.
   Result handling: answer `''` (after trim) → default when set, else failure "'pick' got an empty answer. Answer the
   question or give the block a default."; with choices the answer must equal a choice (a case-insensitive match is
   normalized to the choice's spelling), else failure "Answer 'x' isn't one of the choices of 'pick': a, b."
   Output `{ answer, timedOut: false }`.
2. _Ask timeout_: the common `timeout` aborts `io.signal` as for every block. For ask blocks with a default, a timeout
   is a **success** `{ answer: <default>, timedOut: true }` with an info log "No answer within 60s; using the default
   'dev'." (special-case in `hostBlock` / `interrupted`; cancel stays cancelled); without a default it fails with the
   usual timeout message and `timedOut: true`. Retries re-ask. The question is masked in events like every detail.
3. _Roots_ (`engine/context.ts` `RunScope`): the expression context always has `editor` (`options.editor ??
emptyEditorContext()`) and `git` (`options.git ?? emptyGitContext()`); they are fixed for the run (readable in
   workflow `env` too).
4. _run-start_ (`engine/runStart.ts`): `context.editor` / `context.git` only when RunOptions has them: `selection` and
   `diff` cut like live values (`cutText` + "…", so `isCutString` detects them), `changedFiles` first 200, every string
   masked with the run's secret masker. `origin` copied when given and not manual. The synthetic run-start of hosts
   (ext-run) adds `origin` itself.
5. _Reducer / summary_ (`run/view.ts`): run-start copies `origin` into the view; `runRecordSummary` copies `origin`.
6. _Live values_ (`live/`): `liveContext` copies `context.editor` / `context.git`; `liveValue` evaluates with
   `editor` / `git` when present; a reference to `editor.*` / `git.*` in a run without them → `unavailable` "This run
   didn't record editor values." / "This run didn't record git values.".
7. _Simulation_ (`simulation/`): `createSimulationHost` implements `askUser`: next mock's `answer`, `error` rejects,
   no mock → default ?? first choice ?? `SIMULATED_ANSWER`; counts calls like other hosts calls (delay applies).
   `defaultSimulationResult(ask)` → `{ answer }` with the same rule (literal values as written). `validateSimulation`:
   ask fields `['answer']` ("Use answer."); warning `sim-ask-choice` when an answer is not one of the literal choices
   ("…: 'staging' isn't one of the choices (dev, prod), so the block fails in the simulation.").
8. _Validation_ (`validate.ts`; codes and severities exact):
   - `KNOWN_ROOTS` gains `editor`, `git`; `unknown-root-field` (warning): "editor.path in prompt of 'x' is not known.
     editor has selection, file, language and line." / "… git has branch, changedFiles and diff.".
   - Ask: templates in `question`, `choices[i]`, `default` are checked like other fields; `ask-default-not-a-choice`
     (error) when both are literal and the default is missing from the choices; `ask-duplicate-choice` (warning).
   - `schedule-too-short` (error, path `['on','schedule','every']`): "Schedules run at most once a minute. Use 1m or
     more." (parsable values below 60 s).

**Behavior — project memory:**

5. `executeAgentRequest`: `mode = request.agent.memory ?? 'read'`. With `deps.memory` and mode ≠ none: `read(io.signal)`

**Behavior — git capture** (`captureGitContext(root, { signal, maxDiffBytes, timeoutMs, gitPath })`, never rejects,
never a shell: `execFile` / `spawn` with an argument list; env adds `GIT_OPTIONAL_LOCKS=0`, `GIT_TERMINAL_PROMPT=0`;

   `onDidResolve`) and rejects with an AbortError. `respond` ignores unknown ids and answers outside the choices
   (logs a warning). `cancel(runId)` on cancel and finish; `dispose` rejects everything.

### 3.5 ext-automation — editor and git capture, Run workflow on selection, triggers (C1, C2 host)

**Owns:** `packages/extension/src/context/**` (new), `packages/extension/src/triggers/**` (new);
`packages/extension/test/unit/context/**`, `packages/extension/test/unit/triggers/**` (new); integration
`packages/extension/test/integration/suite/14-triggers-selection.test.ts` (new; fixture files it needs are created at
test time in the temp workspace and removed afterwards — never add `on:` workflows to the shared fixture folder).

**Produces:**

- `createCodeContextCapture(options?: { isTrusted?: () => boolean; captureGit?: CaptureGitContext; log?:
vscode.LogOutputChannel }): CodeContextCapture` (`src/context/codeContext.ts`).
- `registerSelectionCommand(services: Services): vscode.Disposable` (`src/context/selectionCommand.ts`), command
  `isarFlow.runWorkflowOnSelection` (optional argument: a workflow `vscode.Uri`, which skips the QuickPick).
- `createTriggerService(deps: TriggerServiceDeps, options?: TriggerServiceOptions): TriggerService`
  (`src/triggers/triggerService.ts`; options inject clock, timers, ui and settings for tests). It owns its status bar
  item (`isarFlow.triggers`, name "Isar Flow triggers") and registers `isarFlow.showTriggers`.

**Behavior — capture:**

1. `editor(root)`: the active text editor, else the most recently active text editor that is still visible (tracked
   with `onDidChangeActiveTextEditor`; webviews make `activeTextEditor` undefined); documents with schemes other than
   `file` / `untitled` and Isar Flow's own `.workflow.yaml` / `.agent.yaml` files are skipped; none → undefined.
   `selection` = all non-empty selections joined with "\n", cut at 100 KB (UTF-8, character boundary); `file` =
   relative to `root` with forward slashes when inside, else the absolute path, `''` for untitled; `language` =
   `languageId`; `line` = primary selection's `active.line + 1`.
2. `git(root, signal)`: `''`/`[]` values when not trusted (Restricted Mode: git can run repository hooks); otherwise
   `captureGitContext(root, { signal, maxDiffBytes: GIT_DIFF_MAX_BYTES })`; logs how long it took when over 2 s.

**Behavior — Run workflow on selection:**

3. Needs a text editor ("Open a file and select some text, then run a workflow on it."). Takes a snapshot of document
   and selections first (they can change while the QuickPick is open). No workflows → "No workflows yet." [New
   workflow]. QuickPick: workflows with `usesEditor` first (separator "Use the selection"), then the others
   ("Other workflows"); label = name, description = relative path, detail = description; invalid ones show
   "$(warning) Has problems". Placeholder "Run a workflow on the selection" or, with an empty selection, "Run a
   workflow (nothing selected: editor.selection is empty)". Then `runs.start(uri, undefined, { origin: { kind:
'selection' }, editor: <snapshot as EditorContext for the chosen workflow's folder> })`. It does not open the canvas;
   the status bar and the finish notification report the run.

**Behavior — triggers:**

4. Source: `workflows.list()` summaries with `triggers` (re-synced on `workflows.onDidChange`); each workflow's folder
   = the workspace folder of its file. `state(uri)` and `list()` reflect the current gates; `onDidChange` fires on any
   change of a workflow's state.
5. Matching: workspace-relative path (forward slashes) of the event file in the workflow's folder (outside → ignored);
   positive patterns with `globMatcher` from `'../tools/glob'`, `!` patterns exclude; files under `.git/`,
   `node_modules/` and `.isarflow/` are ignored unless a positive pattern starts with that folder; the workflow's own
   file never triggers it. `save` = `workspace.onDidSaveTextDocument`; `change` = one
   `createFileSystemWatcher(new RelativePattern(folder, pattern))` per positive pattern (create, change, delete).
   Watchers exist only while the workflow's triggers are active (enabled, trusted, valid).
6. Debounce 2 s per workflow (events of both kinds coalesce; the run's origin is the last event: `{ kind: 'trigger',
trigger, file }`). At fire time, in order: setting `isarFlow.triggers.enabled` (re-read; `onDidChangeConfiguration`
   updates states and cancels pending debounces when off) → trusted (`onDidGrantWorkspaceTrust`) → valid → not
   `limited` → not running (`runs.active(uri)`; skipped events are recorded in `lastFired.skipped` "The workflow was
   already running.") → `runs.confirmationState(uri)`: `needed` → paused `approval` and, once per workflow and
   session, a notification "Run '<name>' once and choose 'Run and remember' so its triggers can start it." [Open
   workflow]; `invalid` → paused `invalid` → `runs.start(uri, {}, { origin, onRefused })`; refusals become state
   (`inputs` → paused `inputs`, `confirmation` → paused `approval`, others → `lastFired.skipped` with the message).
7. Own writes: while a run of the workflow is active its file events are dropped (not queued); after its
   `onDidFinish` events are dropped for 3 s, and events for files in `changedFiles` for 10 s.
8. Storm guard: more than 10 save/change starts of one workflow within 10 minutes → paused `limited`, warning
   "'<name>' started 10 times in 10 minutes, so its triggers are paused." [Resume triggers] [Open workflow];
   `resume(uri)` clears it. Schedules don't count.
9. Schedule: one 15 s ticker compares `Date.now()` with each workflow's `nextRunAt` (first = now + every when the
   trigger appears or changes); a due schedule fires once and sets `nextRunAt = now + every` (also when skipped);
   after sleep (`now - nextRunAt > every`) it fires once and logs "Missed N scheduled runs of '<name>' while VS Code
   or the computer was asleep; running it once now." Never more than one start per tick per workflow.
10. Status bar (`isarFlow.triggers`, left, priority 9, after the run item): hidden without workflows with triggers;
    "$(zap) 3 triggers" when active, "$(zap) Triggers paused" when all are paused or the setting is off; tooltip
    (MarkdownString) lists workflows with their trigger labels and state; command `isarFlow.showTriggers` →
    QuickPick of those workflows (state as description) → Open workflow / Resume triggers (limited) / Turn triggers
    off (opens the setting).

**Edge cases:** trigger storms (a branch switch touching 1,000 files → one run); a workflow that edits files matching
its own trigger; save and change for the same save; schedule while VS Code sleeps; untrusted workspace, then trust
granted; unapproved hash, then approved; setting turned off with a pending debounce; workflow invalid, deleted,
renamed or its `on:` removed (watchers disposed); multi-root; patterns with `!`; `.isarflow/memory.md` written by
remember (ignored); two workflows triggered by one save; no editor open, an untitled editor, multi-cursor selection,
a selection over 100 KB, a file outside the workspace; not a git repository, detached HEAD (from core).

**Tests:** unit with fake timers, a fake RunManager and store, and runtime-patched vscode APIs (watchers, save events,
configuration, trust): capture rules; selection command ordering, placeholder, refusal paths and the URI argument;
every trigger gate and state transition, debounce coalescing, own-write suppression, storm guard and resume, schedule
ticks and sleep catch-up, status bar text / tooltip / visibility, disposal. Integration (`14-triggers-selection`):
create a workflow with `on: { save: { files: 'notes-c.txt' } }` and a console block in the temp workspace, save
`notes-c.txt` → a run with origin trigger appears in the history; run the selection command with a workflow URI
argument while a text editor with a selection is active → the run's `editor.selection` is recorded in its context.
