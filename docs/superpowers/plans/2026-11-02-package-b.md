# Package B — implementation plan

Date: 2026-11-03 · Spec: `docs/superpowers/specs/2026-11-02-isar-flow-packages-design.md` (Package B, sections B1–B3).
Builds on Package A (`docs/superpowers/plans/2026-11-02-package-a.md`), which is finished and must not regress.
Exclusion confirmed by the owner: **no MCP server** — no module builds one.

Package B makes workflows faster to build: **Run from here** continues a finished run at a block (B1), **live
values** show what templates evaluated to in the last run (B2), and **test mode** simulates a run with mocks (B3).
Six modules build it against frozen contracts in two waves; an integration step wires the rest, runs the slow test
levels once and writes the docs.

### 1.1 Schema (`schema/types.ts`, `schema/simulation.ts`, `schema/jsonSchema.ts`)

| Addition                                                                    | Meaning                                                                                                                                                                                   |
| --------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `SimulationResult`                                                          | One mocked host call: console `exitCode?`, `output?`; agent `text?`, `json?`; approval `approved?`, `comment?`; any of them `error?` (fails the call).                                    |
| `SimulationApprovals = 'approve' \| 'reject'`                               | Answer for approval blocks without mocks (default approve).                                                                                                                               |
| `SimulationFile { version?: 1; approvals?; blocks?: Record<id, Result[]> }` | Contents of `.isarflow/simulations/<name>.sim.yaml`. Results are used in order; the last repeats.                                                                                         |
| `SimulationResultSchema`, `SimulationFileSchema` (zod, strict)              | Block ids follow `STEP_ID_PATTERN`; `exitCode` integer; `error` non-empty; `version` only 1. A single object instead of a list is a schema error (the parser gives a friendlier message). |
| `simulationJsonSchema()`                                                    | JSON Schema (title `Isar Flow simulation mocks`) for the YAML extension.                                                                                                                  |

Example file (format decided here; the spec's example lists block ids at the top level, they now live under
`blocks:` so settings like `approvals` can never clash with a block id):

```yaml
version: 1
approvals: approve # or reject
blocks:
  tests:
    - exitCode: 1
      output: '1 failed'
    - exitCode: 0
  review:
    - json: { approved: false, issues: [x] }
    - json: { approved: true, issues: [] }
```

Tested in `packages/core/test/schema-package-b.test.ts`.

## 2. Rules for every module

- Read the spec (Package B), this plan, the v1 spec §11 (test concept) and, for UI work, `docs/ui-design.md`.
- Edit only the paths your module owns. Other modules work at the same time: ignore their in-progress files and type
  errors outside your paths. Never edit the frozen contract files (section 1). Do not regress Package A.
- No git state changes in the repository (no commit, stash, checkout, reset, add). No `npm install`.
- TDD: failing test first, then the implementation. Style: 2 spaces, single quotes, printWidth 110, prettier, no
  `any`, small focused files, comments only when non-obvious. User-facing copy: sentence case, plain verbs,
  actionable errors; no "A · B" meta strings (separate chips or spans), no "→" in buttons. Never lose user data.
- Machine limits (Windows 11, 6 GB RAM, a GPU driver that can freeze the machine):
  - Vitest: run your project and paths only (`npx vitest run --project core packages/core/test/resume`); add
    `--maxWorkers=2` for whole-project runs.
  - Integration tests (`npm run test:integration -w isar-flow`): only one VS Code test instance at a time, always
    with `--disable-gpu` (already in `packages/extension/test/integration/runTests.mjs` — check with grep; if it is
    missing, do not run them). Take the lock by creating the directory `%TEMP%\isarflow-vscode-test.lock` with
    `mkdir` (atomic); if it exists, wait (PowerShell `Start-Sleep 30`) and retry; always remove it afterwards, also on
    failure. Use `ISAR_TEST_GREP` to run only your tests.
  - Playwright (`scripts/visual.mjs`, `scripts/interactions.mjs`): one browser at a time with the lock directory
    `%TEMP%\isarflow-playwright.lock` (same protocol); always pass `--only=…` (and `--themes=dark,light,hc` only when
    needed). Read the PNGs in `packages/webview-ui/visual-output/`; zero page errors required.
- Commands: `npx vitest run --project <core|extension|webview-ui> [paths]`,
  `npx tsc --noEmit -p packages/<pkg>/tsconfig.json`, `npx eslint <paths>`, `npx prettier --check <paths>`.
- Done means: your tests pass; `tsc` passes for every package you touched (errors only in other modules'
  in-progress files are acceptable — name them); eslint and prettier are clean on your files; coverage gates hold
  (core ≥ 90 %, extension ≥ 70 %). The final report lists changed files, contract change requests, things the
  integrator must wire, and short user-guide snippets for your features (docs are written in the integration step;
  do not edit `docs/`, `README.md`, `CHANGELOG.md` or `examples/`).

### 3.1 core-resume — resume in the engine, run-start context and hashes, reused events, preview (B1, B2 core)

**Owns:** `packages/core/src/engine/**` except `types.ts`; `packages/core/src/run/**` except `types.ts` (new
`run/blockHash.ts`, `run/resume.ts`; exports in `run/index.ts`); `packages/core/test/engine/**`;
`packages/core/test/run/**`; `packages/core/test/resume/**` (new); `packages/core/test/fakes/fakeHost.ts`.

**Consumes:** `RunOptions.resume / simulated`, `ResumeOptions`, `ResumedFrom`, `RunContextSnapshot`, run-start
`resumedFrom / simulated / context / blockHashes`, step-end `reused`, `StepRunView.reused / outputTrimmed`,
`RunView.resumedFrom / simulated / context / blockHashes`, `ResumePreview`, `ResumeLoopPoint`,
`RunRecordSummary.resumedFrom / simulated / stoppedAt`, `SECRET_MASK`, `walkSteps` / `findStep` / `stepChildren`.

**Produces** (exported from `@isar-flow/core` through `run/index.ts`):

- `blockHash(step: Step): string` — hash of the block's own YAML content: the parsed step without `name` and without
  child lists (`steps` of loops, `then` / `else` of ifs), keys sorted recursively (arrays keep their order), JSON
  text, hashed with a synchronous 53-bit string hash (cyrb53) → 14 lowercase hex characters, zero-padded. Isomorphic
  (no `node:crypto`); tolerates lenient steps (odd values, unknown keys).
- `blockHashes(workflow: Workflow | null | undefined): Record<string, string>` — every block with a string id
  (document order; the first of duplicate ids wins); `{}` for null.
- `resumePreview(workflow: Workflow, run: RunView, stepId: string): ResumePreview`.
- `resumeOptions(workflow: Workflow, run: RunView, stepId: string): ResumeOptions` — throws `Error(blocker)` when the
  preview has a blocker.
- `runStoppedAt(run: RunView): string | undefined`.
- Engine: run-start fields; `RunOptions.resume`; reducer and summary changes below.

**Behavior:**

1. _run-start_ always carries `blockHashes: blockHashes(workflow)` and `context`: `env` = sorted unique keys of
   `options.env` plus the workflow's `env` keys; `secrets` = sorted keys of `options.secrets`; `workflow` =
   `{ name, file: options.workflowFile ?? '' }`; `workspace` = `{ root: options.workspaceRoot }`. With
   `options.simulated` it carries `simulated: true`; with `options.resume` it carries
   `resumedFrom: { runId: resume.fromRunId, stepId: resume.stepId }`. No env or secret value ever appears in an event.
2. _Resume_ (document order = `walkSteps` pre-order). Find the target with `findStep`; its ancestors are the
   containers on its path. A target that is not in the workflow ends the run before any block: run-start, then
   run-end `failure` with `Block '<id>' isn't in the workflow anymore, so the run can't continue there. Run the whole
workflow instead.` Resume mode is on from the start until the target starts:
   - A block before the target that is not an ancestor is **reused**: for it and for each of its descendants (document
     order) that has an entry in `resume.outputs`, emit `step-end { status: output.status, output, error:
output.error, durationMs: 0, at: now, reused: true }` and set `steps[id] = output`. Blocks without an entry get
     no event and no seed (missing). A reused block has no effect on the flow: a reused `break` / `stop` / failure does
     nothing, and no host is called.
   - An ancestor **loop** gets its normal step-start and continues at `N = loopIterations[id]` (missing, < 1 or not an
     integer → 1). The resumed iteration skips the `while` check and the limit check, emits `loop-iteration N` (limit
     = the loop's current `maxIterations`), and runs its body in resume mode; then the loop goes on normally (`until`
     check, then iteration N + 1 with `while` and limit checks). Output `iterations` counts from N. When N > 1, every
     descendant of the loop that has a stored output (the target included) is seeded into `steps` silently (no event)
     before the body runs — in a normal run they would hold the previous iteration's output.
   - An ancestor **if** takes the branch that contains the target without evaluating its condition; the other branch
     is skipped as usual; output `{ branch, result: branch === 'then' }`.
   - The **target** runs normally (resume mode ends when it starts; its templates see the seeded outputs), and so does
     everything after it. Agent sessions (`session: continue`) start empty. Usage and the token budget count only
     executed blocks. Abort, retries and timeouts behave as in a normal run.
3. _Reducer_ (`run/view.ts`): run-start copies `resumedFrom`, `simulated`, `context`, `blockHashes` into the new view
   (when present). A `reused` step-end sets `status`, `output`, `error`, `durationMs: 0`, `reused: true`, keeps
   `executions` (0 when it never started), adds no metrics and no usage to the run total. A later step-start of the
   block clears `reused` (it is re-executed, e.g. in the next loop iteration).
4. _Summary:_ `runRecordSummary` copies `resumedFrom` and `simulated`; for failed and cancelled runs it sets
   `stoppedAt = runStoppedAt(view)`: among steps with status failure or cancelled and not reused, the one with the
   greatest `startedAt` (ties: the one later in `view.steps`); omitted when there is none. `blockRunMetrics` already
   skips reused steps (no metrics).
5. _resumePreview:_
   - `blocker`: target not in the workflow → `This block isn't in the workflow anymore.`; `run.status === 'running'`
     → `Wait until the run has finished.`; `run.simulated` → `Simulated runs can't be continued. Run the workflow,
then run from a block.` With a blocker every list is empty.
   - "Before" blocks = blocks before the target in document order that are not ancestors, without the blocks of an
     ancestor if's branch that does not contain the target (those are skipped).
   - `reused` = before blocks with `run.steps[id]?.output`; `missing` = the others.
   - `changed` = reused blocks whose `run.blockHashes[id]` differs from `blockHash(current step)` or is missing (only
     when `run.blockHashes` exists); `changesUnknown = !run.blockHashes`.
   - `trimmed` = reused with `outputTrimmed`; `masked` = reused whose output contains `SECRET_MASK` in any string.
   - `loops` = ancestor loops, outermost first: `iteration = run.steps[id]?.loop?.iteration ?? 1`,
     `maxIterations` = the current value (non-numbers → 5, like the engine's default).
   - `forcedBranches` = ancestor ifs whose stored `output.branch` is `then` / `else` and differs from the target's
     branch.
   - `freshSessions` = agent blocks with `session: 'continue'` at or after the target (document order) whose
     `run.steps[id].executions > 0`.
6. _resumeOptions:_ `{ fromRunId: run.runId, stepId, outputs: { [id]: run.steps[id].output } for every step with an
output, loopIterations: from preview.loops }`.

**Edge cases:** target is the first block (nothing reused) or a top-level block; target is a container (runs normally
from iteration 1 / evaluates its condition); nested loops (each continues at its own iteration); a loop whose earlier
iterations failed (continueOnError — reused outputs are the latest iteration's); stored iteration past the current
limit; a loop that never ran in the source run (iteration 1); target in the branch the source run did not take; blocks
after the target in the same loop body; cancelled and failed source runs; reused skipped blocks; reused failures;
reused `stop` / `break`; abort during the resumed iteration; retries of the target; source runs without
`blockHashes` / `context` (older versions); lenient workflows (blocks without ids are never reused; duplicate ids);
`resume` and `simulated` together.

**Tests (core unit, FakeHost; coverage ≥ 90 %):** `blockHash` stability (key order, `name` ignored, child changes don't
change the container's hash, prompt changes do, lenient values); `blockHashes` nested; run-start `context` (names
only — assert that no env or secret value occurs in any emitted event) and `blockHashes`; resume at a top-level block
(earlier blocks reused with events, host never called for them, the target's templates see seeded outputs); resume
inside a loop at iteration 3 (loop-iteration starts at 3, no `while` check, `iterations` output, `until` ends it,
silent seeding visible to the target's templates, blocks after the target run); nested loops; if forced to `else`;
target is a loop; missing target → failure text; missing outputs; reused failure does not fail the run; run usage and
budget exclude reused blocks; reducer (`reused` flag, no metrics or usage, executions 0, cleared on a later start);
`runRecordSummary` (`resumedFrom`, `simulated`, `stoppedAt` for failure, cancel, continueOnError cases, none for
success); every `resumePreview` field incl. blockers, trimmed and masked; `resumeOptions`.

### 3.2 core-live-sim — live values and the simulation file, ops and host (B2, B3 core)

**Owns:** `packages/core/src/live/**` (new), `packages/core/src/simulation/**` (new), `packages/core/src/index.ts`
(add `export * from './live';` and `export * from './simulation';` only), `packages/core/test/live/**` (new),
`packages/core/test/simulation/**` (new).

**Consumes:** `LiveContext`, `LiveValue`, `LiveValueType`, `RunView`, `SimulationFile`, `SimulationResult`,
`SimulationApprovals`, `SimulationFileSchema`, `SimulationHostOptions`, `SimulationHost`, `EngineHost` request and
result types, `findTemplateExpressions`, `analyzeExpression`, `evaluateExpression`, `stringifyValue`, `SECRET_MASK`,
`shapeToJsonSchema`, `checkJsonShape`, `extractJson`, `findStep`, the YAML helpers in `yaml/` (`PARSE_OPTIONS`,
`describeYamlError`, position mapper, `schemaDiagnostics` where they fit).

**Produces — live values** (`live/`):

- `LIVE_VALUE_MAX_CHARS = 2048`.
- `liveContext(run: RunView): LiveContext` — `inputs` and every defined step `output`, deep-copied with each string
  longer than 2,048 characters cut to 2,048 plus `…`; `loops` from each step's `loop` (`{ iteration, index:
iteration - 1 }`); `env`, `secrets`, `workflow`, `workspace` from `run.context` (fallbacks: `[]`, `[]`,
  `{ name: run.workflowName, file: '' }`, `{ root: '' }`); `runId`, `startedAt`, `status`, `simulated` copied. Pure.
- `liveValue(context: LiveContext, expression: string, scope?: { workflow?: Workflow | null; stepId?: string | null
}): LiveValue` — `expression` is the source between `${{` and `}}`:
  1. Parse error → `{ kind: 'error', message }` (the evaluator's message).
  2. References (via `analyzeExpression`): any `env.*` → unavailable `Environment values aren't saved with runs.`;
     `steps.<id>` without an output in the context → unavailable `<id> has no result in this run.`; `loop.*` when the
     scope block is not in a loop → unavailable `loop is only set inside a loop.`
  3. Evaluate with `{ inputs, steps, env: {}, secrets: names → SECRET_MASK, workflow, workspace, run: { id: runId },
loop }`, where `loop` = the iteration of the innermost loop that contains `scope.stepId` (the block itself when
     it is a loop: its `until` / `while`). Evaluation error → `{ kind: 'error', message }`.
  4. Value → `{ kind: 'value', text, type, truncated, masked }`: `text = stringifyValue(value)` cut to 2,048;
     `type`: string → `text` (empty string → `empty`), number, boolean, array → `list`, object → `object`,
     null / undefined → `empty`; `truncated` when the text was longer or contains a string that `liveContext` cut;
     `masked` when the text contains `SECRET_MASK`.
- `templateAt(text: string, offset: number): TemplateMatch | undefined` — the template whose span contains the offset
  (`start <= offset < end`); never throws (unterminated templates → undefined).
- `lastConditionResult(step: unknown, context: LiveContext): boolean | undefined` — for a lenient step record with an
  id: `if` → `steps[id].result` when boolean; `loop` with `until` → exitReason `condition` → true, `maxIterations` →
  false; `loop` with `while` → `condition` → false, `maxIterations` → true; otherwise undefined.

**Produces — simulation** (`simulation/`):

- `SIMULATED_ANSWER = '(simulated answer)'`.
- `parseSimulationText(text: string): { file: SimulationFile | null; diagnostics: Diagnostic[]; blockRanges:
Record<string, Range> }` — YAML parse like workflow files (same options, error texts and ranges); empty document →
  `{}`; `blocks:` with no value → `{}`; a single result object instead of a list → error `Use a list of results for
"<id>", e.g. "- exitCode: 0".`; other schema errors from `SimulationFileSchema` with ranges; `file` is null when
  there are errors; `blockRanges` = the range of each block key.
- `validateSimulation(file: SimulationFile, workflow: Workflow, blockRanges?: Record<string, Range>): Diagnostic[]` —
  warnings with `stepId` and the key's range; codes `sim-unknown-block`, `sim-no-host-call`, `sim-field-mismatch`,
  `sim-json-shape`:
  - unknown id → `No block "<id>" in this workflow. Remove its mocks or fix the id.`
  - loop / if / break / stop → `"<id>" is a <type> block; only console, agent and approval blocks use mocks.`
  - fields of another type → `Result <n> of "<id>": <field> doesn't apply to <type> blocks. Use exitCode and
output.` (agent: `Use text, or json for JSON answers.`; approval: `Use approved and comment.`)
  - `json` for a text agent → `Result <n> of "<id>": this agent answers with text, so json is ignored. Use text.`
  - `json` that doesn't match the JSON fields (`checkJsonShape`) → `Result <n> of "<id>" doesn't match the JSON
fields: <problems>.`
- `checkSimulationText(text: string, workflow: Workflow | null): { file: SimulationFile; diagnostics: Diagnostic[] }`
  — parse plus validate (validate only with a workflow); `file` is `{}` when parsing failed.
- `setSimulationResults(text: string, stepId: string, results: SimulationResult[] | null): string` —
  comment-preserving (yaml `Document` API like `yaml/ops.ts`): empty text → start from `newSimulationText`; creates
  `version: 1` / `blocks:` when missing; replaces the block's list; null or [] removes the key; other blocks and
  comments stay; block style; result keys in the order exitCode, output, text, json, approved, comment, error;
  multi-line strings as `|` block scalars. YAML errors in `text` → throws `Error("The simulation file can't be read:
<first error>. Fix it in the file first.")` (never loses data).
- `renameSimulationBlock(text: string, oldId: string, newId: string): string` — renames the key in place (position and
  comments kept); unchanged when `oldId` has no mocks or `newId` already has some.
- `newSimulationText(workflowName: string): string` — a header comment that explains the format with one commented
  example per block type, then `version: 1` and `blocks: {}`; parses to an empty file without diagnostics.
- `sampleJson(shape: OutputShape | undefined): unknown` — through `shapeToJsonSchema`: object → every property
  (required and optional), string → `'(simulated)'`, number / integer → 0, boolean → true, array → [], null → null;
  `const`, then `default`, then the first `enum` value win; anyOf / oneOf → the first; unknown → null; no shape →
  `{}`.
- `defaultSimulationResult(step: Step, approvals?: SimulationApprovals): SimulationResult` — console `{ exitCode: 0,
output: '' }`; text agent `{ text: SIMULATED_ANSWER }`; JSON agent `{ json: sampleJson(schema), text: <that JSON,
pretty> }`; approval `{ approved: approvals !== 'reject' }`; others `{}`.
- `createSimulationHost(options: SimulationHostOptions): SimulationHost` — a call counter per stepId; call n uses
  `blocks[stepId][min(n, length) - 1]`, else the default. Each call: wait `delayMs` (abortable); an aborted signal
  rejects like a cancelled host call; `error` rejects with `new Error(error)`; first log line (stream `info`):
  `Simulated: result 2 of 3.`, `Simulated: result 3 of 3 (the last result repeats).` or `Simulated with the default
result.`
  - `runConsole`: `{ exitCode: r.exitCode ?? 0, stdout: output, stderr: '', output, timedOut: false }`; the output is
    logged on `stdout`.
  - `runAgent`: JSON answers (`req.output?.format === 'json'`): `json = r.json ?? (r.text !== undefined ?
extractJson(r.text) : sampleJson(req.output.schema))`, `text = r.text ?? JSON.stringify(json, null, 2)`; text
    answers: `text = r.text ?? SIMULATED_ANSWER`, no json. Logs the text on `agent`. Returns `{ text, json, model:
req.agent.model, usage: { inputTokens: 0, outputTokens: 0 }, turns: 1, toolCalls: 0, messages: [...req.history,
{ role: 'user', content: req.prompt }, { role: 'assistant', content: text }] }`.
  - `requestApproval`: `{ approved: r.approved ?? file.approvals !== 'reject', comment? }`; logs `Answered
automatically: approved.` / `… rejected.`
  - `calls()` returns a copy. Never reads files, runs commands or calls models.

**Edge cases:** huge outputs (cut once at 2 KB, `truncated` set); secrets in outputs (already masked → `masked`);

loops consuming results in order; abort during `delayMs`; approval blocks with `onReject: continue`.

**Tests (core unit; coverage ≥ 90 %):** `liveContext` cutting, loops, fallbacks; `liveValue` tables (values of each

   and templates in the text, a disclosure under the field: `Values from the last run (3)` / `Values from this run
(3)`, collapsed by default; expanded: one row per distinct expression — code token, a one-line preview (ellipsis),
   IconButton `Copy value of <expr>` (posts `copyToClipboard`); activating a row shows the full value (≤ 2 KB)
   with the same notes. Fully keyboard reachable.
5. _Condition results:_ when no run is shown (`source: 'last'`), the If header and the Loop summary show a Chip `Last
run: true` (icon `pass`) or `Last run: false` (icon `circle-slash`) from `lastConditionResult` (tone outline, AA
   contrast); with a shown run the lanes and iterations already tell. The ConditionBuilder's live summary appends
   `Last run: true` / `This run: false` as a separate muted span whenever a value is known.
6. _Simulation section_ (`simulation/SimulationSection.tsx`, mounted by `BlockSettings` for console, agent and approval
   blocks when `simulation` is known): a Section `Simulation` (open when the block has mocks), hint `Results Simulate
uses for this block, in order. The last one repeats.`; one row per result, labelled `Call 1`, `Call 2`, and the last
   with a `Repeats` chip:
   - console: Field `Exit code` (number, placeholder 0) and Field `Output` (TextArea, code font, autoGrow);
   - text agent: Field `Answer` (TextArea); JSON agent: Field `Answer (JSON)` (code TextArea; new rows start with the
     pretty `sampleJson` of the block's fields; invalid JSON shows `Not valid JSON: <reason>` and is not saved);
   - approval: SegmentedControl `Decision` (`Approve` / `Reject`) and Field `Comment`;
   - every row: Switch `Fail this call` revealing Field `Error message` (default `Simulated failure`); IconButtons
     `Move call 2 up`, `Move call 2 down`, `Remove call 2`.
   - Button `Add result` (icon `add`). Without results a muted line names the default: `Without results, Simulate uses
exit code 0 and no output.` / `…, the agent answers "(simulated answer)".` / `…, the agent answers with sample
JSON built from its JSON fields.` (plus the sample) / `…, the approval is approved.` (or `rejected.` per
     `approvals`).
   - Warnings for this block from `simulation.diagnostics` (by `stepId`) in a warning Banner; file errors in an error
     Banner `The simulation file has errors, so Simulate won't start.` with `Open simulation file`; a link-style button
     `Open simulation file` at the end.
   - Edits use a draft (commit after 350 ms idle and on blur, like `useRowsDraft`): `setSimulationMocks(stepId,
results.length ? results : null)`; defaults that equal the placeholder are left out of the result (`exitCode: 0`
     is written only when typed).
